Getting started

  1. Download the zip for your system from the download section and unzip it. Compare its SHA-256 with the one shown next to the file: shasum -a 256 <file> on macOS and Linux, Get-FileHash <file> in PowerShell.
  2. Run it once. Builds are not signed yet, so your system warns the first time.
    • macOS: move Bikasend.app to Applications, open it and close the warning. Go to System Settings → Privacy & Security and click Open Anyway. On macOS 14 and earlier you can right-click the app and choose Open.
    • Windows: choose More info → Run anyway. If the window stays blank, install the Microsoft Edge WebView2 runtime. It comes with Windows 11.
    • Linux: install GTK 3 and WebKitGTK 4.1 with sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0 or sudo dnf install gtk3 webkit2gtk4.1.
  3. Open a folder. Click Open folder… and pick a repo. Bikasend lists every operation it finds, grouped by tag, and opens the last folder again when it starts. If the folder has a .bika.json, Bikasend asks you to trust it first.
  4. Pick an operation. Filter by path or summary, toggle methods, or paste a URL to find its operation. The URL, parameters, headers and an example body come filled in. Pick an environment to fill the variables.
  5. Send. Press ⌘ Enter or Ctrl Enter; press it again to cancel. You see the status, time, size, headers and body, and every place the response breaks the spec’s schema.

Which files it reads

When you open a folder, Bikasend looks at every file below it and parses the ones that match all of these:

  • The name contains swagger or openapi, in any case, and ends in .json, .yaml or .yml. For example openapi.yaml or docs/example-service.swagger.json.
  • The file has a top-level swagger field (Swagger 2.0) or openapi field (OpenAPI 3.0 and 3.1). Other matching files are left out quietly.
  • It is not inside a folder named .git, node_modules or vendor.
  • It is not a YAML file with a JSON twin: when openapi.yaml and openapi.json sit side by side, only the JSON file is read.

Every read goes through the opened folder, so nothing outside it is read, not even through a symbolic link. A $ref can point into the same file or to another file in the folder by a relative path. The target must be a .json, .yaml or .yml file whose path has no hidden (dot) part. Remote $ref URLs are refused.

The YAML reader handles block and flow collections, scalars and block scalars. It refuses anchors, tags and files with more than one document.

A file can be at most 20 MB, and all specs in a folder together at most 200 MB. A file that fails to parse shows its error on its own entry; the other files still load. Bikasend reloads when a spec it found or .bika.json changes on disk. A new spec file shows up when you rescan the folder (↻).

From the folder, Bikasend reads only these specs, the files their $refs point to, .bika.json, the TLS files it names, and files you pick yourself for an upload.

Variables and scopes

Write {{"{{name}}"}} anywhere in a request: the URL, a header, a parameter or the body. Bikasend fills it in just before it sends. It looks the name up in four scopes, the narrowest first, and the first hit wins:

ScopeLives inShared
SessionThe app’s memory, gone when you quitNo
Environment.bika.json → environments.<name>.variablesYes, through git
Folder.bika.json → variablesYes, through git
GlobalYour own globals.json in the Bikasend folder of your user config folderNo

When no scope defines {{"{{baseUrl}}"}}, Bikasend uses the spec’s server. A spec with more than one server gets a picker, and Bikasend remembers your choice per spec.

A value can use other variables, up to 10 levels deep; a loop is an error. A name that no scope defines stops the send and says which one is missing. To send the literal text {{"{{text}}"}}, write {{"{{{{text}}}}"}}. Names use letters, digits, ., _ and -, up to 64 characters.

Press ⌘ E or Ctrl E to open the variables panel. Hover a variable in a request to see where its value comes from.

The .bika.json file

.bika.json sits at the top of the opened folder and is meant to be committed, so the whole team shares the same environments. It holds where a secret lives, never the secret. Bikasend creates it, with a local environment, the first time you save a shared variable, an environment or a host.

Bikasend ignores the file until you click Trust. Trust pins the file’s exact content (its SHA-256). Your own edits in Bikasend keep the trust; when anything else changes the file, Bikasend asks again. Review it like code first, because it decides which secrets load and which hosts get them. A file larger than 1 MB, or one that is a symbolic link, is refused.

A complete example

{
  "variables": {
    "tenant": "demo"
  },
  "environments": {
    "local": {
      "hosts": ["localhost:8080"],
      "variables": {
        "baseUrl": "http://localhost:8080",
        "api_key": { "prompt": "Local API key" }
      }
    },
    "staging": {
      "hosts": ["api.staging.example.com", "*.auth.example.com"],
      "aws": { "profile": "staging", "region": "eu-west-1" },
      "timeoutSeconds": 30,
      "followRedirects": false,
      "tls": {
        "caFile": "certs/staging-ca.pem",
        "certFile": "certs/client.pem",
        "keyFile": "certs/client-key.pem"
      },
      "oauth2": {
        "tokenUrl": "https://login.auth.example.com/oauth2/token",
        "clientId": "example-client",
        "clientSecret": "{{"{{client_secret}}"}}",
        "scopes": ["items.read"]
      },
      "variables": {
        "baseUrl": "https://api.staging.example.com",
        "api_key": { "aws": "example-service/api-keys", "key": "bikasend" },
        "client_secret": { "ssm": "/example-service/client-secret" },
        "ci_token": { "env": "EXAMPLE_TOKEN" }
      }
    },
    "signed": {
      "hosts": ["*.execute-api.eu-west-1.amazonaws.com"],
      "aws": { "profile": "staging", "region": "eu-west-1" },
      "sigv4": { "service": "execute-api" }
    }
  }
}

Top level

variables
Folder variables, used in every environment.
environments
One entry per environment. The name uses letters, digits, ., _ and -. Bikasend picks local first when it exists, and remembers your last environment per folder. A name that starts with prod asks before every send.

Environment fields

hosts
The hosts that may receive secrets, such as api.example.com, localhost:8080 or *.example.com. *.example.com matches every name under example.com, but not example.com itself. A wildcard needs at least two labels after it, so *.com is refused. With a list, loopback hosts must be listed too. See Secrets and hosts.
variables
Environment variables. They win over folder variables of the same name.
aws
profile and region for the aws CLI when Bikasend loads secrets or signs requests.
timeoutSeconds
0 to 600. Left out or 0 means 2 minutes.
followRedirects
true or false. Left out means Bikasend follows up to 10 redirects.
tls
caFile adds a CA to the system ones; certFile and keyFile are a client certificate. Paths are relative and stay inside the folder; absolute paths and .. are refused.
oauth2
Client credentials: tokenUrl and clientId are required, plus clientSecret and scopes. All of them can use variables. clientSecret must be a variable, such as {{"{{client_secret}}"}} pointing to AWS or asking for it: Bikasend refuses the secret itself in a shared file. The token URL must be https (http only on loopback), and its host must be in hosts. Bikasend keeps the token in memory until it expires.
sigv4
AWS Signature V4: service is required; region falls back to the one in aws. Bikasend signs with the credentials of the aws profile.

You pick OAuth2 or SigV4 per request in its auth settings. Any other field is an error, so a typo shows up at once. There is no proxy field: a proxy is a personal setting in the app.

Variable values

FormValue
"demo"Plain text, sent as written.
{"prompt": "Label"}Bikasend asks for the value once per session and keeps it in memory.
{"aws": "secret-id"}An AWS Secrets Manager secret. Add "key": "name" to read one field of a JSON secret.
{"ssm": "/parameter/name"}An AWS Systems Manager Parameter Store parameter.
{"env": "NAME"}An environment variable of the Bikasend process. It must be set and not empty.

Each object form takes exactly one source. Everything except plain text counts as a secret.

Bikasend refuses plain text under a name that looks secret, in .bika.json and in globals.json. A name looks secret when it contains key, token, secret, password, passwd, credential, auth, cookie or private, unless it ends in url, uri, host, endpoint or path. A value made only of {{"{{references}}"}} is fine. globals.json holds variables only, no environments.

Secrets and hosts

Secrets come from four places: values you type into the session, prompts, environment variables, and AWS Secrets Manager or Parameter Store. AWS values load into memory through your own aws CLI and its login. Click Load secrets, or Sign in with AWS SSO when you are signed out. Bikasend runs the CLI without a shell. When you switch environment, it forgets the AWS values it loaded.

Secrets stay in the app’s memory. They are not written to disk or to a log, and the window shows them masked until you click Reveal. History is kept in memory unless you turn on saving in Settings; on disk, secret-looking values are masked. When a server echoes a request’s secret back, Bikasend masks it in the response.

Before every request that carries a secret, Bikasend checks where it goes:

  • With a hosts list, a secret goes only to a listed host. A host outside the list is blocked; you can open the hosts editor, then send again.
  • Without a hosts list, a secret goes to loopback hosts (localhost, 127.0.0.1, ::1, *.localhost) without asking. For any other host, Bikasend asks: Send once, or Always allow to add the host to the environment’s list.
  • Plain http to a host other than loopback needs your confirmation on each send.
  • Redirects: a request with a secret does not follow a redirect to another host, or from https to http.

The checks matter because a request URL can come from a spec file that anyone with access to the repo can change.

Copy as code

Use Copy as… on a request, or the command palette, to copy it as cURL, PowerShell, HTTPie, JavaScript fetch or Python requests. Variables are filled in, and every part is quoted for its language.

Secrets never reach the clipboard. Each one becomes an environment variable with a BIKASEND_ prefix, such as $BIKASEND_API_KEY, and a comment at the top lists the ones to set. Bikasend refuses to copy a request when a secret would still show up, for example URL-escaped or too short to replace, or when the text holds control or bidirectional characters. OAuth2 and SigV4 are not copied; a note says what to add.

Updates

When it starts, Bikasend asks this site whether a newer version is out. You can turn that off in Settings; it is the only call the app makes on its own. When an update is out, the version in the top bar changes to Update to …. Click it to download the build for your system into your Downloads folder, or your home folder if there is none.

Before it offers to install, Bikasend checks the file three ways:

  1. its SHA-256 against the hash this site lists,
  2. against the hash GitHub lists for the release, and
  3. against the release’s SHA256SUMS file, which must carry a valid signature from the project’s release key. That key stays offline with the maintainer, so neither this site nor the GitHub account alone can ship an update.

If any check fails, Bikasend deletes the file. When all three match, it shows you the results, and Update and restart replaces the app and starts the new one. Open request tabs come back after the restart, with secret-looking values masked, unless you turned Reopen tabs on start off in Settings. If Bikasend cannot replace the app where it runs, it says why; unzip the saved file and replace the app yourself.

Bikasend only updates to a newer version, from the site built into it.
